# 轻量级多模态 RAG 开发计划

> 项目仓库：`C1audel3/KnowFlow`
> 开发分支：`feat/simple-multimodal-rag`  
> 文档版本：v1.6
> 制定日期：2026-09-14
> 最近更新：2026-09-16

## 1. 项目目标

基于 RAG-Anything 和 LightRAG，开发一个可独立演示的轻量级多模态知识库问答系统。系统支持上传 PDF、Markdown 和图片，能够索引文本、图片、表格和公式，并通过统一问答界面返回答案及来源信息。

该项目的首要目标是形成一个稳定、可测试、可展示的完整闭环，而不是覆盖上游项目的全部功能。

## 2. MVP 范围

### 2.1 必须实现

- 使用 OpenAI-compatible API 接入 LLM、视觉模型和 Embedding 模型。
- 支持 PDF、Markdown、PNG、JPG 文件。
- 支持文本、图片、表格和公式四种内容类型。
- 支持直接插入 `content_list`，用于快速验证多模态链路。
- 支持真实文档解析与入库。
- 支持 `mix` 检索模式的知识库问答。
- 返回答案、来源文件和处理耗时。
- 提供文档上传、处理状态和问答接口。
- 提供一个简单的 Streamlit 演示页面。
- 提供基础单元测试、接口测试和固定问答测试集。

### 2.2 暂不实现

- 用户注册、权限管理和多租户。
- 音频、视频处理；虽然上游已支持，但不纳入首版演示。
- 分布式任务队列和多节点部署。
- PostgreSQL、Neo4j、Milvus 等外部存储。
- 模型微调和复杂 Agent 工作流。
- 大规模自动化 RAG 评测平台。

## 3. 技术选型

| 层次 | 选型 | 说明 |
|---|---|---|
| 开发语言 | Python 3.11/3.12 | 与项目 CI 范围保持一致 |
| RAG 框架 | RAG-Anything + LightRAG | 多模态处理及混合检索 |
| 文档解析 | MinerU | 首版只使用默认解析器 |
| API | FastAPI + Uvicorn | 提供清晰、可测试的服务接口 |
| 演示界面 | Streamlit | 用最少代码完成上传和问答页面 |
| 模型协议 | OpenAI-compatible API | 便于切换云端或本地模型服务 |
| 数据存储 | LightRAG 默认本地存储 | 降低部署复杂度 |
| 测试 | pytest + pytest-asyncio | 单元与异步集成测试 |

## 4. 计划目录结构

```text
RAG-Anything/
├── app/
│   ├── api/                  # FastAPI 路由
│   ├── core/                 # 配置、日志和异常
│   ├── schemas/              # 请求与响应模型
│   ├── services/             # RAG 与文档任务服务
│   └── main.py               # API 入口
├── ui/
│   └── streamlit_app.py      # 演示页面
├── data/
│   └── samples/              # 小型演示文档
├── scripts/
│   └── evaluate.py           # 固定问题集评测脚本
├── tests/
│   └── app/                  # 新应用层测试
├── report/                   # 计划、设计和结果文档
└── raganything/              # 尽量不侵入的上游核心代码
```

原则：业务代码放在 `app/` 和 `ui/`，只有确认上游能力不足时才修改 `raganything/`。

## 6. 推荐 API 范围

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/health` | 服务与模型配置检查 |
| `POST` | `/documents` | 上传并启动文档处理 |
| `GET` | `/documents/{task_id}` | 获取处理状态 |
| `POST` | `/query` | 执行知识库问答 |
| `GET` | `/config/public` | 返回非敏感运行配置 |

首版不提供物理删除知识库接口，避免误删本地存储。开发期间通过新的 `working_dir` 隔离测试数据。

## 7. 测试计划

### 单元测试

- 文件类型及大小校验。
- `content_list` 数据转换。
- 请求和响应模型校验。
- 模型配置读取。
- 服务异常到 HTTP 状态码的映射。

### 集成测试

- 插入纯文本后可以查询固定事实。
- 插入表格后可以查询指定数据。
- 图片处理函数收到有效的图片数据。
- 文档处理状态可以从 `processing` 转换为 `completed` 或 `failed`。

### 手工验收问题

- 文档的主题是什么？
- 表格中某一行对应的数值是多少？
- 图片展示了什么，其与正文有什么关系？
- 公式中的变量分别代表什么？
- 文档没有提供某项信息时，系统能否明确说明未知？

## 8. 风险与控制

| 风险 | 控制方式 |
|---|---|
| MinerU 安装和模型下载较重 | 先用 `content_list` 跑通，再接真实 PDF |
| LightRAG 内部 API 变化 | 固定依赖版本，应用层避免调用私有属性 |
| Embedding 维度不匹配 | 启动时验证模型名称和维度 |
| VLM 调用成本较高 | 使用小型样例、限制图片大小和测试次数 |
| 本地任务状态重启后丢失 | README 明确单进程演示限制，后续再引入持久队列 |
| 回答看似合理但无依据 | 固定事实问题、展示来源、加入“未知”测试 |

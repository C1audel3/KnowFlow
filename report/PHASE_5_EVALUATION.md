# 阶段 5：测试与评估报告

> 完成日期：2026-09-16
> 评测模型：DeepSeek V4.1 Flash、Ollama `bge-m3`
> 原始结果：[`artifacts/phase5_results.json`](./artifacts/phase5_results.json)

## 1. 阶段成果

阶段 5 建立了可重复执行的轻量评测闭环，并补齐服务并发、生命周期和真实模型集成测试：

- `app/evaluation.py`：评测数据模型、逐题规则检查、故障隔离和聚合统计。
- `scripts/evaluate.py`：通过 HTTP 调用实际 FastAPI 服务的一键评测入口。
- `data/evaluation/phase5_questions.jsonl`：16 题固定测试集。
- `tests/test_evaluation.py`：数据集、规则、异常隔离、耗时统计和密钥保护测试。
- `tests/app/test_phase5_concurrency.py`：查询限流、读写并行、关闭等待和重复上传隔离测试。
- `tests/integration/test_phase5_real_api.py`：默认跳过、显式开启的 DeepSeek + Ollama 集成测试。

评测器只依赖公开 HTTP API，不直接访问 LightRAG 内部对象。单题请求失败会记录安全错误码并继续执行，避免一次网络波动丢失整轮结果。

## 2. 固定数据集

问题来自阶段 2 提交的 PDF、Markdown 和 PNG 样例，分布如下：

| 类型 | 题数 | 验证内容 |
|---|---:|---|
| 文本 | 4 | 项目名称、发布时间、负责人等正文事实 |
| 表格 | 3 | 传感器数值、延迟和准确率 |
| 图片 | 3 | 路线图节点、连接关系和目的地 |
| 公式 | 2 | 均值公式及变量含义 |
| 跨文档 | 2 | PDF 与 Markdown/图片信息组合 |
| 拒答 | 2 | 文档未提供的信息不得编造 |
| 合计 | 16 | 六类能力 |

每题可声明三类确定性规则：`expected_keywords` 要求全部出现，`expected_any` 要求至少出现一个，`forbidden_keywords` 要求全部不出现。比较时忽略英文大小写。

该方法适合小型项目回归，但只能衡量“固定规则命中率”，不能代表人工评审或通用语义准确率。

## 3. 运行方式

先使用阶段 2 知识库启动单 worker API，再执行评测：

```bash
WORKING_DIR=./rag_storage_phase2 \
  uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1

python -m scripts.evaluate \
  --api-url http://127.0.0.1:8000 \
  --rounds 2 \
  --fail-on-check
```

可选真实集成测试必须显式授权：

```bash
RUN_REAL_INTEGRATION=1 python -m pytest -m integration
```

普通 `python -m pytest` 不会调用真实模型。结果文件记录模型名但不记录密钥和 API 地址。

## 4. 真实评测结果

提交的结果使用 16 题执行两轮，共发起 32 次真实 HTTP 请求：

| 指标 | 结果 |
|---|---:|
| 请求成功率 | 100%（32/32） |
| 非空回答率 | 100%（32/32） |
| 固定规则命中率 | 100%（32/32） |
| 拒答规则命中率 | 100%（4/4） |
| 各类别规则命中率 | 均为 100% |
| 端到端平均耗时 | 131.88 ms |
| 端到端 P50 | 125.50 ms |
| 端到端 P95 | 137.45 ms |
| 后端平均耗时 | 129.97 ms |
| HTTP/客户端平均开销 | 1.91 ms |

这两轮是在前一次评测已经建立查询缓存后执行，因此延迟代表“已有查询缓存命中”的重复问答性能，不能作为首次生成延迟。阶段 4 的单个未缓存页面问题曾耗时 14,626 ms，两组数据口径不同，不做直接性能承诺。

第一次评测时，请求成功率和非空回答率均为 100%，但一个拒答用例错误地把其他传感器的已知数值设为禁用词，导致正确的解释性拒答被误判。修正规则仅禁止把这些数值归给未知的 Sensor-D，随后使用同一批回答重新验证为 100%。这是测试规则缺陷，不是模型答案修改；该过程说明拒答测试应限制“错误归因”，而不是禁止答案引用证据。

## 5. 自动化覆盖

新增测试覆盖：

- JSONL 空集、非法行、重复 ID 和类别分布。
- 全部命中、任一命中、禁用词和拒答判断。
- 某一请求异常后继续评测其余问题。
- 多轮统计、P50/P95、后端耗时和 API 开销。
- 输出中不出现 API Key。
- 查询并发上限确实生效。
- 文档处理中仍可执行查询。
- 服务关闭等待活动文档任务，再释放存储。
- 同名重复上传具有独立任务 ID 和隔离路径。

真实集成测试检查阶段 2 知识库、Ollama 可用性和 DeepSeek 查询结果；默认通过 `RUN_REAL_INTEGRATION` 开关跳过，避免持续集成环境产生费用。

## 6. 简历可用表述

推荐使用可验证且不过度外推的表述：

> 设计 16 题多模态固定回归集，覆盖文本、表格、图片、公式、跨文档与拒答场景；通过 FastAPI 完成 2 轮共 32 次真实模型请求，请求成功率与固定规则命中率均为 100%，并记录逐题结果、分类指标及 P50/P95 延迟。

不建议写“模型准确率 100%”或“平均响应仅 132 ms”：前者把关键词规则扩大为语义准确率，后者忽略了查询缓存。

## 7. 已知限制

- 测试集规模小，内容来自项目自带合成样例，不代表开放领域表现。
- 关键词规则无法识别所有同义表达，也不能完整判断事实一致性。
- 当前来源字段仍可能为空，尚未进行引用准确率评测。
- 延迟受本地硬件、网络、服务端负载和缓存状态影响。
- 尚未加入 LLM-as-a-judge、人工双盲评分、召回率或大规模压力测试。
